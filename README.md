## 5. Согласованность при конкурентном доступе

Устранил четыре класса состязаний, каждый из которых приводил к нарушению гарантий распределения остатка. Все исправления проверялись параллельными запросами на развёрнутом стеке.

- **Атомарный захват членства при постановке в очередь.** Параллельные запросы одного пользователя более не приводят к расхождению его состояния. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/8147a87d424e787525aaacf4b780d4251ed71e36))
- **Соблюдение порядка FIFO при распределении остатка.** Освободившаяся единица товара достаётся первому участнику очереди, а не тому, чей запрос поступил раньше. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/4d1f0060c42362eeb588be86328664b89ff0d17a))
- **Аренда отложенных переходов вместо изъятия из расписания** (`service/expiration.go`). Обработчик берёт задачу истечения в аренду. Прекращение работы процесса в середине обработки приводит к возврату задачи в расписание по истечении аренды, вследствие чего удерживаемые единицы не остаются заблокированными. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/0a99747544181f14cb962540d570008cf027d307))
- **Атомарный захват членства при принятии частичного предложения.** ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/e70a6662cc2b854d706be1921398ca165545545a))

## 6. Восстановление состояния после сбоя

Переработал восстановление кэша из PostgreSQL таким образом, чтобы противоречивые записи приводились к согласованному состоянию, а не препятствовали запуску. В исходной редакции единственная противоречивая запись оставляла сервис в непрерывном цикле перезапуска. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/6f6701dcbdb382abd60c87fe36a5f79c7aca9dac))

Предусмотрены следующие правила приведения:

- отрицательный доступный остаток приводится к нулю с фиксацией в журнале;
- активное право, на которое не ссылается ни одно членство, переводится в состояние `EXPIRED`;
- членство без действующего права переводится в состояние `DECLINED`, то есть приводится к состоянию, которое было бы достигнуто по истечении срока;
- исправления фиксируются в PostgreSQL до перестроения Redis, вследствие чего повторный запуск не обнаруживает тех же расхождений.

Дополнительно устранил ошибку в тесте репозитория, приводившую к нарушению ограничения внешнего ключа. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/7c2eb27ecb02b0be9dca6a3ee64fd74ef4c2c2b6))

## 9. Прочее

**Временная заглушка сервисного слоя.** На начальном этапе, до готовности бизнес-логики, реализовал заглушку, отвечавшую по окончательному контракту: состояние определялось исключительно входными данными и временем, без учёта остатка. Это позволило клиентской части приступить к интеграции, не дожидаясь готовности серверной. Заглушка удалена мною при подключении реального сервисного слоя. ([Commit](https://github.com/bigboynixxik/team-10-queue-serivce/commit/c86798e40089abc7571248185f91baa276b2f5cf))

**Ревью ветки с исправлением критических ошибок.** Проверил на развёрнутом стеке серверную проверку права, доставку списания остатка при недоступной внешней системе, восстановление после полной потери Redis и отсутствие регресса по состязаниям. Выявленные дефекты устранены.
